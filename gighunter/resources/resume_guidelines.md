# Resume & Cover Letter Guidelines

Rules the `/tailor-resume` skill must follow. Each rule is tagged with its source.
Add new sources by appending a section and listing the URL under **Sources**.

**Sources**
- [Harvard] https://careerservices.fas.harvard.edu/resources/create-a-strong-resume/ (read live 2026-11-16)
- [FocusGTS] https://www.focusgts.com/8-elements-of-an-effective-technical-resume/ (the live site blocks automated fetches; read from the Wayback Machine copy, snapshot 2026-01-22)
- [Project] Conventions for this repo, *not* from a source. Change them freely.

## 0. Non-negotiable: truthfulness
- Every employer, title, date, degree, certification, number and tool must come from `aboutme.md` or `source_resumes/`. Nothing is invented, estimated or "rounded up". [Project]
- If a strong bullet needs a metric that isn't in the sources, **ask the user**. Never make one up. [Project]
- Rewording, reordering, and choosing what to emphasize are fine. AI should edit, not be "the primary author", and the content must "authentically represent who you are". [Harvard]
- Matching keywords from the job description is encouraged **only when the experience is real**. [Harvard, FocusGTS]

## 1. Structure & order
- Put sections in order of importance for the target role. [Harvard]
- Within a section, go most recent first. [Harvard]
- Avoid unexplained gaps. If one exists, ask the user how to address it. [Harvard, FocusGTS]
- Make the current or most recent role easy to judge: title, tenure, scope. [FocusGTS]
- Show progression: responsibilities, not just titles, because titles vary by company. [FocusGTS]
- Give company context when the employer's tech or domain is relevant. [FocusGTS]
- Header logistics: location, relocation openness, and work eligibility if relevant. Email **and** phone are required. [FocusGTS, Harvard]
- Keep Education and add Certifications/Courses, but "experience is king". [FocusGTS]
- Default section order for technical roles: Header → Summary (2–3 lines, optional) → Technical Skills → Experience → Projects → Education & Certifications. [Project]

## 2. Formatting
- Be consistent in format, spacing, bold, italics and capitalization. Balance white space. [Harvard]
- Make it skimmable. First pass is about 6 seconds. [FocusGTS]
- It must survive PDF conversion. Single column, no tables, text boxes or graphics, for ATS parsing. [Harvard; ATS detail is Project]
- Don't start lines with dates. Dates go right-aligned or at the end of the role line. [Harvard]
- One page under about 10 years of experience, two pages max otherwise. [Project]

## 3. Bullets & language
- Specific, not general. Active voice. Fact-based: quantify and qualify. Show results. [Harvard]
- "Express, not impress": no flowery wording. [Harvard]
- Pattern: **Action verb + what + how/tools + measurable result**. [Project, consistent with Harvard]
- Past tense for past roles, present tense for the current role. [Project; the sources don't say]
- 3–6 bullets per recent role, fewer for older roles. [Project]
- Action verbs (Harvard list, sampled): Achieved, Built, Collaborated, Conducted, Coordinated, Designed, Diagnosed, Directed, Documented, Engineered, Established, Implemented, Investigated, Launched, Led, Maintained, Modeled, Optimized, Orchestrated, Overhauled, Presented, Programmed, Redesigned, Reduced, Resolved, Simplified, Spearheaded, Standardized, Streamlined, Supervised, Tested, Trained, Upgraded, Validated.

## 4. Omit
- Personal pronouns (I, we), narrative style, slang. [Harvard]
- Photo, age, gender, references. [Harvard]
- Abbreviations. [Harvard] *Exception:* standard technical acronyms that ATS searches for (SQL, AWS, CI/CD) stay. Where the job description spells one out, write both once, e.g. "Amazon Web Services (AWS)". [Project; FocusGTS keyword rule]

## 5. Technical resume specifics
- Keywords are deal-breakers because screeners are often non-technical. Mirror the job description's exact terms for skills you really have. [FocusGTS]
- Include web presence: GitHub, portfolio, blog. [FocusGTS]
- Be ready to foreground specific technologies the listing emphasizes. [FocusGTS]
- Technical Skills section: group by category (Languages, Frameworks, Data, Cloud/DevOps, Tools) and put the job's must-haves first. [Project]

## 6. Cover letter [Harvard unless noted]
- It's a writing sample and a screening step. One page max, concise and factual, no flowery language.
- Address a specific person when one is known. Otherwise use "Dear Hiring Manager" [Project].
- Research the organization and tailor the letter to it.
- Write from the reader's side: why you can do *this* job.
- Reference skills from the job description and back them with concrete examples from the sources.
- Don't overuse "I". Use plenty of action words.
- Same font and size as the resume. Check it after PDF conversion.
- Shape (from Harvard's sample): date → recipient → opening (role + where you found it) → 1–2 evidence paragraphs with quantified results → thank-you close.
